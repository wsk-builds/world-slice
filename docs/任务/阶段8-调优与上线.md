# 阶段 8 · 调优、平台接入、上线（T102–T109）

> 执行规则和技术约定见根目录 `任务清单.md`。每一项默认都要通过 `npm run check` 和 `npm test`；下面的「AI 自查」只写额外要求。
> 阶段目标：GDD §9.3 的包体规定、§11 的测量、§12 的上线核对项。
> 平台的规则和接口会变。这个阶段每一项动手前都要先查平台当前的官方文档，文档和 GDD 不一致时以文档为准，并告诉用户。

### T102 发布开关与功能裁剪

依赖：T101　GDD：§9.3「硬规定」

**做什么**

1. `DEBUG` 开关：发布构建里，调参面板、摆关器、挂机自测、美术测试台、调试快捷键、网址参数全部进不去。构建脚本加"调试版 / 发布版"两种。
2. 功能裁剪：关掉 3D 物理、2D 物理（Box2D）、骨骼动画（含 Spine / DragonBones）、地形、视频等用不到的模块（玩法物理采用纯 TS 的 `TorusWorld3D`），引擎只留 2D 和基础 3D 网格渲染。在完成记录里列出最终的开关清单。
3. 微信端打开引擎插件分离。

**你来验**：出一个发布版真机包：找不到任何调试按钮，游戏照常能玩。

### T103 🔶 分包与后台加载

依赖：T102　GDD：§9.3「分包」

**做什么**

1. 主包只有引擎、启动代码和加载画面。
2. 核心分包是第一幕需要的全部内容，加载完就能玩。
3. 其余内容按幕拆包，在后台加载；玩到某一幕时还没加载完，就显示加载画面等它。
4. 在 `Res` 的表里填好每个资源属于哪个包。
5. 需要用户在编辑器里把文件夹设成分包的，一步一步写清楚点哪里。

**你来验**：出真机包：第一次打开很快就能进第 1 关；直接从选关进第五幕（用调试版解锁），等一下也能正常进。

### T104 包体与性能检查

依赖：T103　GDD：§9.3、§1（机型）

**做什么**

1. `tools/size-report.mjs`：构建后列出主包、各分包、总包的体积，以及最大的 20 个文件。对照主包 4MB、总包 20MB（以平台当前文档为准）。
2. 检查：图片是否都是 WebP；有没有没用到的资源被打进包。
3. 性能：对象池、`Graphics` 数量、DrawCall、内存。在一台低端安卓真机上测 12 个圈加角色加机关时的帧率。
4. 输出问题清单，修掉其中纯代码的问题；需要重做图的列给用户。

**你先准备**：一台尽量旧的安卓手机（安卓 10 左右）。

**你来验**：看 AI 给的体积表，主包和总包都在限制以内；在旧手机上玩最复杂的一关（第 28 关）和第 30 关，不卡。

### T105 微信正式接入与提审自查

依赖：T104、T062　GDD：§7、§12「上线准备期核对的平台与合规信息」

**你先准备**：微信小游戏的正式 AppID、每个广告点各自的广告位 ID、分享用的图片。

**做什么**

填入正式 AppID 和四个广告位 ID；分享的标题和图片；隐私授权弹窗和用户协议入口；胶囊按钮和刘海的安全区复查；AI 生成内容的标识（按平台当前要求）。对照微信小游戏的审核规范逐条自查，输出一张"过 / 不过 / 需要你确认"的表。

**你来验**：真机上四个广告点各点一次，能看到真广告，看完有奖励；看 AI 的自查表，处理"需要你确认"的项。

### T107 难度与时间调优

依赖：T101　GDD：§5 表格下方"难度只有时间一个旋钮"、§6.3「难度」

**你先准备**：找几个人从头玩，或者把自己每关的用时和失败次数发给 AI。

**做什么**

逐关调时间（只调时间）。标准：前 3 关几乎不可能失败；越往后越紧，但续时一次应该能过；首领战多数人第一次或续时一次能过。输出一张表：每关的时间、试玩的通过情况、这次改了多少。二周目的收紧系数一起定。

**你来验**：看那张表，挑你觉得最难和最简单的两关各玩一次，确认感觉对。

### T108 👤 提审与上线

依赖：T105、T106、T107　GDD：§10、§12

**你做**

1. 确认软著、备案、开发主体、流量主都办好了（`任务清单.md` 第五节）。
2. 在微信和抖音的后台填资料、上传发布版、提交审核。
3. 审核意见回来后，把原文发给 AI。

**AI 做**

1. 列出两个平台提审各需要哪些材料，逐项打勾。
2. 帮忙写简介、关键词（往"怀旧""套圈""水机"这类搜索词靠）、更新说明。
3. 根据审核意见列出要改什么，改完重新出包。
