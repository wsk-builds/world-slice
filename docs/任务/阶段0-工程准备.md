### T001 🔶 初始化 Cocos 工程与 Git

依赖：无　GDD：§1、§9.3

**做什么**

1. 在工作区根目录（和 `GDD.md` 同级）建 Cocos Creator 3.8.8 工程：从 `C:\CocosCreator\3.8.8\resources\templates\empty-2d` 复制模板文件。做法照旧项目 `C:\Users\l\cursor\xiaoyouxi-001\docs\进度.md` 的第 2 项，文件结构可以对照旧项目根目录。现有的 `GDD.md`、`任务清单.md`、`AGENTS.md`、`docs/` 原样保留。
2. `package.json` 的 `name` 用 `tao-le-ge-quan`。
3. 设计分辨率 1624 × 750、按高度适配（`settings/v2/packages/project.json`，对照旧项目同名文件）。
4. `settings/v2/packages/engine.json`：2D 模板默认关掉了 `3d` 模块，本项目的圈和柱子要用 3D 网格，把基础 3D 打开；3D 物理、骨骼动画、地形、视频保持关闭；2D 物理用 Box2D。改之前先读模板里这份文件的实际字段。
5. 按 `任务清单.md` 第三节的目录结构建文件夹，空文件夹放 `.gitkeep`。
6. `assets/scenes/Main.scene`：只有 Canvas 和 Camera，Canvas 上挂 `assets/scripts/Boot.ts`（场景怎么引用脚本，对照旧项目的 `assets/scenes/Game.scene` 和 `GameScene.ts.meta`）。`Boot` 暂时只在屏幕正中显示"套了个圈 · 工程就绪"。
7. `.gitignore` 照旧项目；`git init`；首次提交。

**AI 自查**：让 Cocos 把项目导入一遍，没有报错，`temp/tsconfig.cocos.json` 已生成。场景里脚本引用如果怎么都接不上，改为请用户在编辑器里把 `Boot` 拖到 Canvas 上，步骤写清楚。

**你来验**：打开 Cocos Dashboard →「项目」→「添加」→ 选本文件夹 → 用 3.8.8 打开。编辑器下方的控制台没有红字；双击 `assets/scenes/Main`，点 ▶ 预览，浏览器里看到"套了个圈 · 工程就绪"。

**备注**：本文件夹的名字里有一个长横线「—」。如果导入或构建因为路径报错，停下告诉用户，不要自己改文件夹名。

**完成记录 T001**：
- 新增：`package.json`、`tsconfig.json`、`.gitignore`、`.creator/`、`settings/v2/packages/`、`assets/scenes/Main.scene`、`assets/scripts/Boot.ts` 及各目录 `.gitkeep` 与编辑器生成的 `.meta`。
- 自行决定：`engine.json` 除开启 `3d` 与 Box2D、关闭 3D 物理/地形/`skeletal-animation`/`video` 外，一并开启 `primitive`（供后续 3D 占位网格使用）并关闭 2D 骨骼模块 `spine`/`dragon-bones`；`tsconfig.json` 加 `skipLibCheck: true` 规避引擎内置声明报错；`settings/v2/packages/scene.json` 默认指向 `Main.scene`。

### T002 检查工具链与种子随机数

依赖：T001　GDD：§4.2 底线 3（"不是真随机"）

3. `tests/core/purity.test.ts`：扫描 `assets/scripts/core/` 下所有文件，出现 `from 'cc'` 就失败。
4. 确认 `node_modules/` 在 `.gitignore` 里。

**AI 自查**：两条命令都通过。临时在 `core/` 里加一行引用 `cc` 的代码，确认 `npm test` 会变红，再删掉。

**你来验**：在 Cursor 下方的终端里输入 `npm test` 回车，看到全部 passed。

**完成记录 T002**：

- 已实测：`npm run check` 通过；`npm test` 2 个测试文件 4 条用例全部通过；临时在 `SeededRandom.ts` 写入 `import { Node } from 'cc'` 时 `npm test` 检出违规并变红，删掉后恢复全绿。

### T003 布局常量与灰盒掌机外形

依赖：T001　GDD：§8、附录（尺寸）

**做什么**

1. `config/LayoutConfig.ts`：以 1624 × 750 为基准写出全部分区：内屏 940 × 575（水平居中）；下巴铭牌区 940 × 85（紧贴内屏正下方）；左右握把；两个喷射键（各 220 见方）；四个道具键（各 100 见方，在喷射键上方，左边玉水漏和牵引，右边点化和齐鸣）；倒计时（内屏上沿正中）；暂停键和关卡号（左上角）；右上角给平台胶囊按钮留空；浊气条（倒计时右侧）。
2. `config/Palette.ts`：灰盒配色。
3. `ui/ShellView.ts`：用一个共享的 `Graphics` 画出外壳（内屏位置挖空）和各分区的占位框，每个框标上名字。外壳画在最上层，内屏里的东西在它下面。
4. 整机根节点 `Machine`：按 `min(屏宽 ÷ 1624, 屏高 ÷ 750)` 等比缩放并居中，窄屏不裁外壳，四周露出来的地方填机身底色。（GDD 没写窄屏怎么办，按此默认，记进完成记录。）
5. `config/TankSpace.ts`：缸坐标工具。原点在内屏左下角，提供百分比和像素互相换算。

**不做**：按键交互、任何物理。

**你来验**：预览里拖动浏览器窗口的边，把它拉宽、拉窄：掌机始终完整、居中、不变形；能看到标了字的内屏、两个大键、四个小键、下巴区、倒计时。

**完成记录 T003**：
- 新增：`assets/scripts/config/LayoutConfig.ts`、`assets/scripts/config/TankSpace.ts`、`assets/scripts/config/Palette.ts`、`assets/scripts/ui/ShellView.ts`、`tests/config/LayoutConfig.test.ts`、`tests/config/TankSpace.test.ts`。
- 修改：`assets/scripts/Boot.ts`（搭建 `Machine`、`TankRoot` 与最上层 `ShellView`，监听窗口变化按 `min(宽/1624, 高/750)` 等比缩放居中）。
- 自行决定：窄屏不裁剪外壳，缩放后上下/左右露出区域用 `Camera.clearColor` 填机身底色 `Palette.shellBody`；左右各两个道具键水平并排置于喷射键上方，顶部留白区放置暂停/关卡号/倒计时/浊气条/胶囊留空；`TankSpace` 百分比按 `0 ~ 100` 计；外壳用四块实心矩形绕开内屏拼合挖空以避免自相交孔洞三角化毛刺。
- 已实测：`npm run check` 与 `npm test`（4 个测试文件共 10 条用例）全部通过，无 lint 错误。
- 未实测：浏览器画面实机效果（内置浏览器连上 `localhost:7456` 时 Cocos 编辑器未切前台刷新，跑的仍是旧缓存画面；新增脚本的 `.meta` 也待编辑器切前台自动生成，由用户切回编辑器刷新后按 F5 验收）。遗留问题：无。
